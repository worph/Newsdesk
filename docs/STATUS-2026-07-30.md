## What was built

- **MCP client** (`ports/mcp/client.ts`) — shared by inference and delivery. Per-call connect/close,
  endpoint auth from the row, error classification that tells the queue whether waiting could help,
  and Beacon-aware catalogue discovery.
- **Inference port** — driver interface with `capabilities.toolCalling`; the `mcp-claude-code` text
  driver; `runStructured` extracts JSON forgivingly, validates with the generated Zod schema, and
  retries **once** with the parse error fed back. Every attempt lands in `inference_calls`.
- **Job queue** — DB-backed, one worker, exponential backoff with full jitter, `Deferred` for "not
  now but not broken", and `RUNNING` rows reclaimed on boot.
- **Schema generation** — `args_spec` → JSON Schema and Zod, one source of truth for the writer's
  `submit_draft`, the review surface and the payload merge. The director's vocabulary is generated
  with `target_id` as a live enum.
- **Director, writer, assistant** — three prompts in `server/src/prompts/*.md`, each delimiting
  ingested text and labelling it untrusted.
- **Payload merge** — `merge(literals, derived, approved slots)`, pure, frozen at approval.
- **Delivery port** — `mcp`, `webhook` and `builtin` drivers; delivery reads the frozen payload and
  never re-merges.
- **Screens** — Queue, Stories (with the spiked view), Story, Review (document, fields, reason and
  angle, what-will-be-sent, history, assistant chat), Settings.
- **PWA** — manifest with `share_target`, service worker for install and push only, VAPID keys
  generated on first boot, notification on every draft that reaches the gate.

## Decisions taken today

| Decision | Why |
|---|---|
| A **`local-sink` target** ships in the dev seed | the dev Beacon has no `discord-mcp`; a sink exercises approval, freeze, ledger and log without a wire, and a target that silently did nothing would look identical to one that worked |
| Prompts are **`.md` files** copied into `dist` at build | a prompt full of JSON examples and backticks is the last thing you want inside a TS string literal |
| A **duplicate attaches to the story it matched** *and* keeps its own dropped row | one story with two sources is the payoff for dropping key-based dedup; the dropped row is what keeps the match visible in the spiked view |
| An **unverifiable dedup verdict is downgraded to NEW** | a `DUPLICATE` naming a story that does not exist would drop a real story against a claim nobody can check |
| Chat and version history order by **`rowid`**, not timestamp | see below — this was a real bug |
| Queue concurrency stays at **1** | the constraint that forced it is gone, but one worker still buys deterministic ordering and no write contention |
| The **textarea** stays; CodeMirror deferred | markdown-it gives a sanitized preview, and the editor is not where the risk is |

## Gotchas found the hard way

1. **A Beacon does not advertise what it aggregates.** `tools/list` returns exactly four tools —
   `overview`, `tool_doc`, `server_doc`, `call` — and *none* of the aggregated ones. Discovery has to
   go through `overview` + `server_doc`. A namespaced `server__tool` name called directly still
   routes correctly, so only discovery needs the indirection.
2. **`claude-code` must be logged in as the user the MCP server runs as.** Otherwise every call
   returns the string `Not logged in · Please run /login`, which fails as "no JSON found" and says
   nothing about auth. Root and `claude` have separate homes and separate logins.
3. **`docker compose up --build` does not refresh `node_modules`.** Compose carries anonymous volumes
   across container recreation, so the new dependency is in the image and invisible in the container.
   `--renew-anon-volumes` fixes it without dropping the database.
4. **`created_at` ties, and a UUID tiebreaker shuffles.** A chat turn writes the user message and the
   reply in one transaction, so their timestamps are identical to the millisecond — and ordering by
   `(created_at, id)` rendered the conversation in random order about half the time. Now ordered by
   `rowid`. Caught only because a test asserted the order.
5. **`Uint8Array.from` no longer satisfies `BufferSource`.** TypeScript now distinguishes
   `ArrayBufferLike` from `ArrayBuffer`, so the VAPID key needs an explicitly-backed array.
6. **Vite rejects unknown Host headers even with `host: true`.** `allowedHosts` is a separate switch.
