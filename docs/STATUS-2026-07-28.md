## What exists

### The app

- **npm workspace** — `shared` (Zod schemas, slot spec), `server` (Fastify), `web` (React + Vite +
  Tailwind), TypeScript project references throughout.
- **Configuration as one validated YAML document.** Charter, personas, sources, targets, MCP
  endpoints. Seeded from `/data/config.yaml` on **first boot only**; the database is the source of
  truth afterwards, so a stale file can never compete with something edited in the UI. The charter is
  append-only and versions only when its text actually changes.
- **Auth** — single user, argon2, signed cookie session; a separate rotatable **ingest bearer token**
  that stringers use and that a session deliberately does not satisfy.
- **SQLite (WAL) + Drizzle**, all 16 tables from `IMPLEMENTATION.md` §3 and the initial migration.
- **Ingest** — `POST /api/v1/submissions` (object or array), `POST /api/v1/ideas`, plus reads for the
  Inbox and the event log.
- **Pre-inference trimming** — timeline watermarking and snapshot line-diffing, so the director is
  handed only what is new. Not a deduplication authority; that stays the director's semantic
  judgement.
- **Screens** — Login, Configuration, Inbox, Idea box. The nav shows all four groups with unbuilt
  screens greyed out, so the shape of the whole app is legible.
- **Packaging** — multi-stage Dockerfile, plain compose, and a Yundera variant following the real
  AppStore convention (AppShield SSO sidecar, `pcs` network, `x-casaos` block).

### The dev stack — `docs/dev-stack.md`


`web` on :5173 (Vite, HMR) · `api` on :8080 (Fastify, `tsx watch`) · `korben` filing every 15 min ·
`n8n` behind `--profile n8n`.

Sign in with **`newsdesk`**; the ingest token is fixed to **`dev-ingest-token`**.

**It expects a Beacon MCP aggregator already running on the host at `http://localhost:3000/mcp/`.**
The stack does not start one and never will — inference and delivery living outside the app is the
whole design.

## Verified, not assumed

Everything below was exercised against a running instance, not reasoned about:

- **Docker image** — first-boot seeding, login, config round trip, `422` on an unpinned destination,
  SPA served, healthcheck `healthy`, state surviving a restart.
- **Ingest, over HTTP** — report considered whole; unknown source refused with a usable message;

  re-file trimmed to *"1 of 3 entries newer"*; an identical re-file considered nothing; snapshot

- **The dev stack on real data** — beacon reachable at **6 ms** through `host.docker.internal`;
  stringer filed 15 korben entries → *"baseline: considered the most recent entry, skipped 14

  considered. The watermark doing its job, and the proof that a stringer keeping no state costs
  nothing.
- **Hot reload** — boot count 1 → 2 on an edit, after the polling fix below.

## Decisions taken today

| Decision | Why |
|---|---|
| npm workspaces, not pnpm | pnpm was not installed; npm workspaces do the same job |
| Configuration is **one YAML screen**, not four CRUD editors | cuts a milestone of frontend work; the tool-discovery picker is Phase 6 |
| Inference ships with the **claude-code text driver only** | matches the account-billing constraint, and proving the harder constraint first makes the tool-calling driver a trivial addition |
| **Significance dropped as a filter** | routing *is* the judgement; a global scalar was a lossy proxy and an uncalibrated one |
| Dev stringer is a **60-line poller**, n8n behind a profile | a stringer is one HTTP POST; the daily loop should not depend on a container whose logic lives outside git |
| A disabled source's filing is **stored**, not refused | losing a filed report is worse than storing one nobody asked for; the Inbox shows why it slept |
| A mixed batch returns **201** and keeps its good rows | one typo'd `source_id` should not cost the other fourteen entries |

## Gotchas found the hard way

Each of these cost real time and would cost it again:

1. **Destination arguments are optional in the live MCP schemas.** `channelId` and `chatId` are
   absent from their `required` lists, so an unpinned destination does not error — it silently posts
   to whatever default the bridge is configured with. This is now a save-time validation rule with
   tests at three levels. It is the single most dangerous thing found all day, and it needs no model
   involvement to happen.
2. **`discord-mcp__send_embed` has no `url` parameter** and no thumbnail. The canonical link goes in
   `footer` or as a markdown link in the body.
3. **Inotify events do not cross a Windows-backed bind mount.** File *contents* arrive, events do
   not, so `tsx watch` and Vite see new bytes and never notice they arrived — edits appear to do
   nothing. Fixed with `CHOKIDAR_USEPOLLING=true` on both services.
4. **`.dockerignore` needs `**/*.tsbuildinfo`, not `*.tsbuildinfo`.** A stale build-info copied into
   the image makes `tsc --build` believe it is up to date, so it emits nothing and the `COPY` of
   `dist/` fails.
5. A shared global regex leaked `lastIndex` between `test()` and `matchAll()`, silently skipping
   matches — the template-root validation never fired. Caught only because a test existed for it.
6. The RSS entity decoder needed numeric and Latin-1 named entities for a French feed, with `&amp;`
   decoded **last** so `&amp;lt;` does not become a tag.

## Next: Phase 2 — the director

The largest and riskiest phase. Build it **headless and test-driven before its screens**.

1. **Inference port** — driver interface with a `capabilities.toolCalling` flag; the `mcp-claude-code`
   driver over StreamableHTTP to the Beacon, per-call timeout 280s.
2. **Job queue** — DB-backed, **concurrency 1**, backoff with jitter on `409`/`5xx`/timeout. Replaces
   the old pipeline's staggered cron, preflight node and error-reclassification code.
3. **Schema generation** — slot spec → Zod → JSON Schema, the single source of truth. The same
   generator produces the director's tool vocabulary with `target_id` as an enum of live targets.
4. **The director prompt** — charter, target catalogue, source hint, the considered slice, and every
   story from the last 30 days included wholesale. No embeddings, no retrieval layer; that becomes
   worth building at roughly ten times this volume.
5. **Applying the result** — `stories`, `story_submissions` (many-to-many, so one story can cite
   several sources), `publications` at `PROPOSED`, and an event per transition.
6. **Screens** — Queue and Stories, including the spiked view with each drop's reason and, for a
   duplicate, the story it matched.

**Exit criteria:** the same release filed by two different stringers yields *one story with two
sources*; a redundant re-file is caught as `DUPLICATE` with a reason you agree with; a deliberately
noisy report produces zero routes and is spiked with an explanation.

### Ready for it

- The submission pipeline works, so **real fixtures accumulate on their own** — leave the dev stack
  running and the director gets a genuine corpus rather than material I invented.
- `submissions.considered` already records exactly what would be handed over.
- Nothing is enqueued yet: every submission lands as `PROCESSED` because there is no director. The
  seam is to move the "something new" case to `PROCESSING` and push a job.

### Watch out for

- **Prompt-injection surface starts here.** Until now nothing read submission text; the director is
  the first component that does. Delimit it, label it untrusted, and keep the output a database row
  rather than an action.
- **`claude-code` is single-session**, so prompt iteration in dev is serialised. Expected, not broken.
- **The dedup regression set is the load-bearing test**: pairs that are the same story in different
  words from different sources, pairs that are genuine follow-ups, pairs that merely look similar.
  Without it, prompt changes are guesses.
